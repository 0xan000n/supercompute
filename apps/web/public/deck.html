Supercompute

A transparent compute network where safety is mutual, and provable.

Proof, not trust
The problem

Pooling compute means trusting a stranger with three things at once.

The contributor
Your key could be misused.
You lend real API credentials to a pool you do not control.
The shared compute
It could be turned to harm.
Nothing stops a request that should never have run.
The requester
Your prompts could be read.
Whoever runs the pool sits in the middle of every call.

Normally you solve all three the same way: you trust whoever runs the pool. That trust is the whole risk.

The idea

So don't trust them. Constrain it, and prove it.

The gate

Every request passes a policy gate, inside a zkVM.

RISC Zero zkVM · authoritative gate
The safety policy
Runs as a program on every single request. Allow and deny alike pass through it. Nothing runs unchecked.

This is the collective-safety mechanism. Shared compute cannot be turned to harm, because the policy is the gate, not a suggestion.

The answer

The answer comes back. The operator never saw the prompt.

Once the gate allows it, the request is proxied through the contributed key and the answer is returned to the requester. It travels sealed the whole way.

Real, and what's next

The cryptography is real. The box it runs in is the next thing we make real.

●Real today
  • Browser-sealed keys.HPKE in the client; the operator holds ciphertext.
  • The zkVM policy gate.Authoritative on every request, allow and deny.
  • Real RISC Zero STARK proofs.Verified offline, no network, no operator.
  • Immutable capabilities, terminal revocation.
  • Local insights.Facet shape computed without exposing prompts.
●Still simulated / WIP
  • The confidential enclave is a Node process today.A real hardware TEE (AWS Nitro, a confidential VM) is the frontier that lets strangers, not only people who trust the operator, contribute safely.
  • No auth or hosting yet.Local demo only.
  • Single-worker prover backpressure.One prover, requests queue behind it.
